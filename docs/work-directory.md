# Справочник долгов и патчей / Work directory

Задача №7, v17.11.114. Первично заполнены открытые долги из действующей
документации и запроса владельца. Это не утверждение о завершённом аудите всех
архивов ПК и всех чатов. Исторические патчи пока сохраняются в прежней истории;
их проверенный перенос является отдельным долгом SHOWCASE-HISTORY.

## Правила записей

- Источник: `assets/work-items.json`, schemaVersion 1. Редактирование через
  проверяемый исходник и выпуск, не через CRM и не через browser storage.
- Только `debt` (Долг) и `patch` (Патч). Незавершённая, частичная или отложенная
  работа остаётся долгом. После завершения менять существующую запись, сохраняя
  номер, код и дату создания; добавить дату реализации, версию и доказательство.
- Номер — постоянный ID справочника, не номер версии. Новые записи получают
  следующий свободный номер; номера не переиспользовать и не перенумеровывать.
  №7 сохранён за запросом справочника. Остальные ID назначены при его создании.
- `createdOn` и `implementedOn`: подтверждённая дата YYYY-MM-DD или null.
  Дата сверки, Git mtime и публикация релиза не заменяют неизвестную дату.
  У долга implementedOn всегда null. Исторический патч может иметь null,
  если реализация доказана, но точная дата не сохранилась.
- Части проекта — несколько тегов из фиксированного словаря. Все выбранные
  фильтры соединяются AND, включая несколько частей. Даты включают обе границы;
  записи без даты исключаются только при активном диапазоне соответствующего поля.
- Поиск включает RU/EN, код и версию. Номер точный. Даты без значения идут
  последними при сортировке по дате. URL сохраняет фильтры и язык, не CRM-данные.
- Нельзя помечать технический патч долгом только из-за будущего развития:
  реализованный узкий scope и оставшаяся работа должны иметь отдельные записи.
  Пользовательская приёмка и автоматические проверки не подменяют друг друга.

## Обновление и проверка

При каждом изменении списка обновить `reviewedOn`, источник и критерии.
Проверки: `node scripts/check-work-directory.mjs` и
`node scripts/check-work-directory-browser.mjs`. Вторая требует Playwright.
Нельзя добавлять секреты, пути VPS, реальные базы или данные людей.

English: permanent item IDs, only Debt/Patch, verified nullable dates, combined
AND filters and source links. Open debts are seeded first; historical patch
import remains a separate item. Unknown dates are never inferred from file
timestamps. CRM format, data and sessions are not modified by this directory.
